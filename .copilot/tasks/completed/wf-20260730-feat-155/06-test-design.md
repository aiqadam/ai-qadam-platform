## Known Test Gaps

1. **E2E fixture-seeding infrastructure does not exist in this repo — the strategy's E2E plan assumed it does.** Investigation of `apps/e2e/playwright.config.ts` and every existing `smoke-event-*.spec.ts` / `smoke-public.spec.ts` / `smoke-tenant.spec.ts` file shows this suite:
   - Targets `https://aiqadam.org` (production) by default, is **not wired into CI** (`apps/e2e/README.md`: "As of 2026-07-26, this suite is not wired into CI at all"), and is read-only.
   - Has **no seed-data harness, no Page Object Model, no auth-session `storageState` fixture, and no way to guarantee a fixture event exists with a specific `starts_at`/`ends_at`/`visibility_scope`/`latitude`/`longitude`.**
   - Every existing event-related spec (`smoke-event-share.spec.ts`) discovers a real event from the live `/events` list and `test.skip`s gracefully if none exists, rather than asserting against seeded data.

   The test strategy's E2E plan (fixture events for each lifecycle state, a members_only fixture, a lat/lng fixture, a public+gated OG-card pair) assumes seeding infrastructure this codebase does not have for this suite. `tests/uat/*.spec.ts` (a different, docker-compose-backed harness driven by the `uat-verification` agentic workflow, not `playwright test` directly) is the actual tool for that kind of fixture-dependent assertion, but is out of TestDesigner's scope per the agent definition (this repo's `tests/uat/` specs are written/run by a separate workflow phase, not this step).

   **Resolution taken:** `smoke-event-detail-lifecycle.spec.ts` was written to match the *actual* established convention — discover-from-live-list-or-skip for anything state-dependent (tab content, members_only gate), and direct hardcoded-nonexistent-id assertions for anything state-independent (404 property, og-card 404). This means:
   - AC-1/2/3's *full block-composition* assertions (agenda renders, speakers grid renders, recap markdown renders, photo gallery grid renders, livestream iframe renders) are **not** E2E-asserted against a guaranteed fixture — only the tab-selection/SSR-routing mechanics are. If a real fixture with the right lifecycle state happens to exist on the target when the suite runs, the written tests will still catch a composition regression only via the `role="tablist"` + `aria-selected` count checks, not via asserting specific block content.
   - AC-6 (venue map rendering) has no E2E at all — only the `parseCoord` unit test. No E2E test was written because there is no reliable way to assert "an OSM iframe with a specific bbox renders" without a guaranteed lat/lng fixture.
   - AC-7's public-event 200+dimensions+cache-bust-query-changes assertion was not written — only the gated/nonexistent → 404 half.

   **Recommendation for follow-up:** if fixture-guaranteed E2E coverage of AC-1/2/3/6/7's full content assertions is wanted, it belongs in `tests/uat/*.spec.ts` against the docker-compose stack (which DOES support seeded fixtures per `AGENTS.md` §6.1's production-readiness / infra obligations), run via the `uat-verification` workflow phase, not this `apps/e2e/tests/smoke-*.spec.ts` lane. Flagging this as a possible scope note for TestRunner/UATRunner rather than silently declaring it done.

2. **AC-5 (forum posting, optimistic prepend) has no E2E coverage, and — contrary to the test strategy's expectation — none pre-exists.** The strategy said "this may already have partial E2E coverage from the original PR 1.3/1.4... TestDesigner should grep `apps/e2e` for an existing forum/questions spec before writing a new one." I ran a case-insensitive grep for `forum|question` across all of `apps/e2e` (both file names and content) — the only hit was `apps/e2e/tests/uat/BP-USR-PWRESET.spec.ts`, which is the unrelated password-reset flow (a false-positive match on unrelated words), and this file `README.md`. **There is no existing forum/questions E2E spec.** I did not write one this pass: the `ForumThread` island's optimistic-prepend behavior needs a signed-in session (this suite has no `storageState` auth fixture at all, for any spec — confirmed via a repo-wide grep for `storageState`/`auth.setup`/sign-in patterns, which only turned up `tests/uat/*` files, a different harness), and inventing one auth mechanism for a single new spec would be a bigger, more architecturally-consequential decision than TestDesigner should make unilaterally in this pass. Flagging as a genuine coverage gap, not silently working around it.

3. **The `invite_only`-vs-`members_only` behavioral-parity gap** (flagged by TestStrategist, confirmed again while writing): reading `[id].astro` lines 79-81, `isGated` is `(visibilityScope is members_only or invite_only) && Astro.locals.auth?.me == null` — there is no role or invite-list check anywhere. Any authenticated user passes `isGated` regardless of whether the event is `members_only` or `invite_only`. No test was written asserting a role-check that doesn't exist in the code (per the strategy's explicit instruction not to invent one). **Recommendation:** file a follow-up issue asking RequirementAnalyst/ImpactAnalyzer whether `invite_only` is intended to mean something stricter than `members_only` (an actual invite-list check) — as it stands, the two visibility scopes are functionally identical in the code, which may not match the business intent implied by having two distinct enum values.

4. **`api-ssr.test.ts` stale-block-removal CI guard** (strategy's Integration Test Plan row 4) — verified by direct read rather than an automated grep-based lint check: `api-ssr.test.ts` (read in full during this pass) has no `describe('fetchEvent'` block; it contains only a pointer comment (lines 554-557) noting the move to `cms.test.ts`. No dedicated regression-guard script was written for this (the strategy suggested "a one-line grep-based lint check" as one option) — a manual code-review catch is the fallback if a future edit re-adds a stale block. Not blocking; noting as a nice-to-have not done.

5. **No `it.skip` anywhere in the new files** — confirmed by construction (every `test.skip(true, "...")` call in the E2E file is a Playwright *runtime* skip driven by live-environment discovery, which is the established convention in every sibling spec in this directory, not an author-time "test not written yet" placeholder).
